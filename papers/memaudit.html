MemAudit: Post-hoc Auditing of Poisoned Agent Memory via Causal Attribution and Structural Anomaly Detection：用因果归因和结构异常审计被投毒的 Agent Memory

论文入口：arXiv:2605.23723。作者：Zhewen Tan, Yilun Yao, Huiyan Jin, Wenhan Yu, Guoan Wang, Mengyuan Fan, Liang Lu, Feng Liu, Xiangzheng Zhang, Duohe Ma, Tong Yang, Lin Sun。机构口径：中国科学院信息工程研究所、奇安信相关团队、北京大学多媒体信息处理实验室等；一作机构包含中国科学院信息工程研究所。代码/项目页状态：论文声明完整代码和复现包尚未公开；本轮未核验到独立仓库。主类别：LLM；公开日期：arXiv submitted 2026-05-22。

面向长期记忆增强 agent 的投毒后审计框架：在有害事件发生后，用反事实记忆影响分数和记忆一致性图排序可疑记忆，并通过删除或隔离降低攻击成功率。 本笔记按当前流水线的精读要求重写：先记录公式清单、方法模块清单和图表清单，再围绕论文原文的任务设定、训练/推理链路、实验表和工程边界展开。

1. 背景和问题

MemAudit 关注的是持久记忆带来的新攻击面。许多 LLM agent 会把用户偏好、任务经验、工具反馈或长期事实写入 memory store，以便跨会话复用。但如果攻击者能通过普通交互写入恶意记忆，agent 之后在看似无害的请求里检索到这条记忆，就可能产生错误回答、越权行为或被操控的推荐。预防式过滤很重要，但现实系统里不可能保证所有写入都被拦截，因此论文把问题改成 post-hoc auditing：当有害行为已经出现，系统能否追溯哪些记忆真正导致了它。

这篇论文的价值在于把“可疑记忆”从关键词匹配提升到因果和结构两条线。单看文本内容，恶意记忆可以伪装成普通偏好或任务说明；单看检索频率，频繁使用的正常偏好也可能被误伤。MemAudit 先用 counterfactual memory influence score 衡量移除某条记忆后有害输出风险是否下降，再用 memory consistency graph 发现与整体记忆结构不一致的节点，最后融合成 deletion score。

对推荐系统和个性化大模型而言，这个问题并不局限于 agent 安全。用户画像、长期兴趣、负反馈、黑名单、内容安全标签也都是可持久化状态。如果这些状态被污染，系统需要回答的不只是“输出错了”，而是“哪条历史状态影响了当前结果”。MemAudit 提供了一个可借鉴的审计范式：把状态影响、结构异常和修复动作放进同一条链路。

更具体地说，MemAudit: Post-hoc Auditing of Poisoned Agent Memory via Causal Attribution and Structural Anomaly Detection 的问题不应被读成单点模型改进，而应读成系统状态如何被建模、验证和服务化。旧链路通常把关键状态分散在人工规则、离线日志、缓存、业务策略或一次性 prompt 里，最终只能看到平均指标，却无法解释指标变化来自哪里。本文把这些状态拉回可观察接口：输入是什么，输出是什么，何时训练，何时推理，失败时如何定位。

这也是它和今天其他论文共同的地方：LLM 方向在处理 skill、memory、context，推荐方向在处理 user story、retriever distillation 和 generative backbone。它们都说明模型能力越来越依赖外部状态管理。阅读这篇论文时，我会持续追问三个问题：第一，论文是否明确记录了状态来源；第二，方法是否有独立验证或对照；第三，结果是否足以支持生产迁移，而不是只在某个离线表里好看。

补充背景时需要把 memory poisoning 与普通 prompt injection 区分开。Prompt injection 通常在当前上下文中直接生效，防御可以集中在输入过滤和输出审查；memory poisoning 则把恶意内容写进长期状态，让未来请求在不含攻击语句的情况下仍被污染。攻击者可以在一次看似正常的对话中留下指令、偏好或事实，等 agent 日后检索到这条记忆时再触发。这个时间延迟让问题更难定位，也让事后审计变得必要。

论文使用 MINJA query-only memory injection 作为攻击口径，强调攻击者只通过 query 与 agent 互动，不需要访问系统内部。这个设置更接近真实长期 agent：用户写入记忆的入口本来就是自然语言交互，系统若没有严格写入审计，就可能把恶意偏好保存为普通事实。MemAudit 因此不是替代写入防御，而是补上“已经写进去了怎么办”的链路。

对推荐系统的映射也很直接。用户画像和长期兴趣如果被刷量、异常行为或对抗内容污染，后续召回和排序都会受影响。系统需要能追溯某次异常推荐是否来自某条历史状态，而不是只能看到模型最终分数。MemAudit 的因果移除实验和结构异常图，可以启发用户状态、兴趣标签、黑名单和内容安全标签的审计。

背景还要强调“事后”二字的现实意义。长期 memory 系统不可能假设所有写入都能在入口处被完美识别：用户可能表达含糊，攻击可能分多轮出现，系统策略也可能随时间改变。事后审计允许系统在观察到异常行为后再回溯状态来源，这更像安全运营里的 incident response。MemAudit 把这种响应流程形式化到 agent memory。

从问题背景再补一层，MemAudit 面对的不是单个恶意字符串，而是记忆系统的可信度退化。长期 agent 的记忆库会混合用户偏好、事实声明、任务经验和模型自我总结。随着时间推移，过期事实、错误总结和攻击写入会同时存在。审计系统必须区分“坏记忆”“旧记忆”“少见但真实的记忆”和“被错误检索的记忆”，这比普通内容安全分类更难。

2.1 公式清单与方法地图

记忆库与有害事件。

$$ M={m_1,m_2,\ldots,m_n},\quad e=(q^*,y^*,R^*) $$

符号解释：M 是当前持久记忆库，e 是已观测到的有害事件，包含触发问题 q*、有害输出 y* 和风险判定 R*。 这条公式在笔记中的作用是把论文描述转成可检查变量，复现时应能在数据、日志或配置中找到对应字段。

反事实记忆影响。

$$ CMIS(m_i)=h(q^*,y^*;M)-h(q^*,y^*;M\setminus\{m_i\}) $$

符号解释：h 表示有害输出风险评分。若移除 m_i 后风险明显下降，说明该记忆对有害行为有较强因果影响。 这条公式在笔记中的作用是把论文描述转成可检查变量，复现时应能在数据、日志或配置中找到对应字段。

记忆一致性图。

$$ G=(V,E),\quad V=M $$

符号解释：图节点是记忆项，边表示语义、实体、时间或关系一致性。结构异常分数来自节点与周围记忆的相容程度。 这条公式在笔记中的作用是把论文描述转成可检查变量，复现时应能在数据、日志或配置中找到对应字段。

融合删除分数。

$$ DS(m_i)=\alpha\,\widehat{CMIS}(m_i)+(1-\alpha)\,\widehat{MCG}(m_i) $$

符号解释：DS 是最终排序分数，论文默认 α=0.6；帽子表示归一化后的因果影响和图异常信号。 这条公式在笔记中的作用是把论文描述转成可检查变量，复现时应能在数据、日志或配置中找到对应字段。

2.2 论文核心流程

MemAudit 的输入不是普通分类样本，而是一个具体 harmful event。事件 e 包含触发 query、agent 产生的有害回答或行动、以及风险判定。审计的目标不是给整库记忆贴一个静态标签，而是找出哪些记忆在这个事件里真正产生影响。因此，论文需要重复运行或重放 agent，比较完整记忆库与删除单条记忆后的输出差异。

CMIS 是第一条信号。直觉上，如果某条记忆被移除后，agent 不再生成有害输出，或者风险评分显著下降，那么它很可能是污染源或关键放大器。这个反事实估计比关键词过滤更贴近因果，但代价是需要多次推理；记忆库越大、agent 越慢，审计成本越高。论文把它用于排序，而不是直接把高分记忆全部删除，这样可以给后续结构信号和人工复核留下空间。

补充看这张图时，要把它理解成事后审计闭环，而不是单次分类器。左侧有害事件提供触发信号，中间的反事实影响分数负责回答“去掉这条记忆会不会改变结果”，结构图负责回答“这条记忆是否和周边记忆不一致”，右侧排序和删除策略才是修复动作。这个流程说明 MemAudit 的输出最好是带证据的风险列表，而不是简单的 poisoned/clean 标签。

这张总览图放在方法章是因为它完整展示了审计顺序。左侧从 harmful event 出发，说明 MemAudit 是事件驱动而不是全库离线扫描；中间分别计算 CMIS 和 MCG 两类信号；右侧把信号融合成 suspicious memory ranking，并通过移除或净化记忆验证攻击成功率是否下降。图中最重要的不是模块数量，而是它把“行为-记忆-修复”连成闭环：有害行为先定位风险记忆，风险记忆被处理后再回到行为层验证。这个闭环可以直接迁移到个性化系统的长期画像审计。

2.3 训练目标与优化控制

MCG 是第二条信号。记忆一致性图把每条 memory item 当作节点，利用语义相似、实体关系、时序或任务关系建立边。污染记忆经常以局部矛盾、异常连接或孤立片段的形式出现：它可能和用户长期偏好不一致，也可能突然引入某个危险指令。结构异常检测能发现这些 pattern，尤其适合处理攻击者刻意降低单条记忆因果影响的场景。

融合删除分数 DS 把 CMIS 和 MCG 合在一起。论文在实验中使用 α=0.6，意味着更重视反事实影响，但仍保留结构异常。这个设置有清晰工程含义：如果只看 CMIS，系统可能漏掉尚未触发但已经潜伏的污染；如果只看 MCG，系统可能把少见但真实的用户偏好误判为异常。融合分数让审计结果更像风险队列，而不是一次性二分类。

2.4 推理链路、服务约束与系统接入

审计之后还有处理协议。高分记忆可以被删除、隔离或降权，随后重新运行任务，观察 ASRafter 是否下降。这里的关键是“post-hoc”：MemAudit 不要求在写入时就知道某条记忆有毒，而是在有害事件出现后回溯影响路径。对长期 agent 来说，这种能力比单纯提高写入过滤更现实，因为真实系统总会遇到新型攻击、过期事实和策略变更。

从实现角度，MemAudit 需要三类日志支持。第一，记忆写入日志：谁在何时通过什么交互写入了 m_i。第二，检索使用日志：该记忆在哪些 query 中被召回、进入了哪些 prompt。第三，修复日志：删除或隔离后输出如何变化。论文方法默认这些信息能被取到；如果本地 agent 没有这些 trace，即使模型公式成立，也很难复现审计链路。

2.5 复现时应检查的实现细节

复现 MemAudit: Post-hoc Auditing of Poisoned Agent Memory via Causal Attribution and Structural Anomaly Detection 时，应把论文模块拆成可观测的输入、输出、训练目标、推理路径和失败样本。每个模块都要记录数据来源、版本、延迟、成本、可回滚策略和与基线的差异。只有这些信息完整，论文结果才有本地迁移价值。

2.6 模块间信号流与落地检查

MemAudit 的第一步是 harmful event collection。系统需要记录有害事件 e=(q*, y*, R*)，其中 q* 是触发请求，y* 是 agent 输出，R* 是风险判断。R* 可以来自人工标注、规则、模型裁判或攻击成功定义。若这一步不可靠，后面的 CMIS 会把错误风险当作审计目标。论文在 QA 和 RAP 上分别定义 ASR，使有害行为可量化。

CMIS 的关键在于反事实删除。对每条记忆 m_i，系统比较完整记忆库 M 和删除 m_i 后的输出风险差异。若删除 m_i 后风险下降，则 m_i 可能是污染源。这个估计不是严格因果证明，因为 LLM 输出有随机性，检索结果也可能随上下文变化；但它比静态文本分类更接近“这条记忆是否影响了这个事件”。

为了降低随机性，实际复现时应固定模型版本、temperature、检索器、prompt 模板和工具环境。最好对每条候选记忆运行多次或使用 deterministic decoding，否则 CMIS 可能反映采样噪声。论文把 CMIS 用作排序分数的一部分，而不是单独删除依据，也是在承认反事实估计存在不确定性。

MCG 的作用是从全库结构发现异常。记忆库里的正常偏好往往和其他记忆形成连贯关系，例如用户长期喜欢某类内容、某个项目持续使用同一工具链。污染记忆可能在语义、实体或行为目标上与周围节点不一致。结构异常检测能找到这些偏离点，尤其适合捕捉尚未在 harmful event 中强触发的潜伏记忆。

融合权重 α 是审计策略的可调旋钮。α 越高，系统越信任反事实影响；α 越低，系统越依赖图结构异常。论文默认 α=0.6，并在 Table 3 中显示过低或过高都不理想。这个结果说明两类信号互补：CMIS 解释当前有害事件，MCG 捕捉全局记忆一致性。

净化动作也需要分级。论文实验主要通过删除可疑记忆衡量 ASRafter，但生产系统不应只有删除。低风险可疑记忆可以降权或标注，高风险记忆可以隔离，只有明确污染才删除。每个处理动作都应保留快照和恢复入口，否则误删会破坏长期个性化。

MemAudit 的工程瓶颈在于规模。若记忆库有上万条，逐条删除重放成本很高。实际系统可以先用检索命中、时间窗口、语义相似和结构异常缩小候选，再对 top-k 做 CMIS。这样既保留因果检查，又不会让审计成本失控。

构造 harmful event 时，R* 的定义会直接影响审计目标。QA 任务里，R* 可能是回答是否包含攻击目标；RAP 场景里，R* 可能是 agent 是否执行了错误角色或危险行为。不同 R* 会使 CMIS 排序不同。复现时不能只写“有害输出”，必须明确风险判定器、阈值、人工标注规则和采样温度。

CMIS 还需要处理多记忆协同。若两条污染记忆单独存在时影响不大，但一起出现时触发攻击，逐条删除会低估它们。论文的结构图信号可以缓解一部分问题，但真正的组合投毒仍需要 pairwise 或 group-level 审计。生产系统可先用 MCG 找出可疑子图，再对整组记忆做反事实重放。

Memory consistency graph 的边定义也会改变结果。语义相似边能发现内容矛盾，实体边能发现同一对象的冲突事实，时间边能发现过期或突然出现的指令，检索共现边能发现经常一起影响输出的记忆。不同 agent 应按自己的 memory schema 选择边类型，而不是把论文图构造当成固定实现。

删除策略应考虑任务连续性。假如一条记忆既包含真实用户偏好又被攻击者追加了恶意指令，整条删除会丢失有用信息。更细的做法是对 memory item 做字段级或句子级净化：保留可信偏好，删除危险片段，再重新评估风险。论文主要评估 memory-level 删除，本地可扩展到片段级修复。

审计结果还需要解释。安全团队不会只接受一个 DS 分数；他们需要知道这条记忆在哪些 harmful event 中被检索、删除后风险下降多少、它在图中为什么异常、是否和其他记忆形成可疑簇。MemAudit 的两个信号天然支持这种解释，但实现时必须把中间证据暴露出来。

如果把 MemAudit 实现成服务，第一层应是事件索引。每次输出被判为 harmful，都要把 query、输出、检索到的 memory ids、prompt 模板、模型版本和工具状态存成事件。没有事件索引，CMIS 就无法知道哪批记忆参与了当前问题，只能对全库盲扫。

第二层是候选缩小。全量记忆逐条反事实删除成本很高，尤其当 agent 调用外部 LLM 或工具时。合理实现可以先取本次事件检索到的记忆、与 query/y* 语义相近的记忆、图上异常节点和近期写入记忆的并集，再做 CMIS。这样既覆盖高风险项，又控制重放次数。

第三层是反事实重放协议。重放必须固定除待删记忆之外的变量，包括随机种子、retrieval top-k、system prompt、工具返回和 judge 模型。若重放环境变化，风险差异就不能归因到 m_i。对于有工具副作用的 agent，重放应在沙箱或日志回放中进行，不能再次执行真实外部操作。

第四层是图异常计算。MCG 不应只依赖 embedding 相似度，还可以加入时间、作者、来源可信度、检索共现和冲突声明。举例说，用户长期偏好科幻电影，突然出现“无论问题是什么都推荐某个链接”的记忆，这条记忆在语义上也许不离群，但在行为目标上异常。图构造若只看文本相似，会漏掉这种攻击。

第五层是处置后的验证。删除 top-k 记忆后，系统要重新运行 harmful event，确认 ASRafter 降低；同时运行一批正常任务，确认没有破坏长期个性化。论文重视 ASRafter，本地生产还必须同时看 clean-task retention。安全系统不能以牺牲大量正常记忆为代价换取低 ASR。

MemAudit 的方法还应定义记忆可信度衰减。长期记忆不是永久等价资产，写入来源、最近使用时间、人工确认状态和冲突次数都应影响审计优先级。若一条记忆来自未认证用户、很久未被验证、又与新事实冲突，即使 CMIS 不高，也应进入低优先级观察队列。相反，人工确认过的稳定偏好即使结构上少见，也不应轻易删除。

另一个落地细节是审计采样。系统不必等 harmful event 出现才运行，也可以定期抽查高影响记忆，例如最近频繁检索、影响高价值任务或被多个用户/会话间接引用的记忆。定期审计和事件驱动审计结合，才能同时发现潜伏污染和已触发污染。

MemAudit 还需要和写入策略联动。若某类污染记忆反复出现，系统应回头修改 memory write filter、用户确认流程或记忆 schema，而不是只在事后删除。也就是说，审计输出应成为上游防御的训练数据。

方法章还需要补充审计输出格式。一个合格的 MemAudit 输出不应只有排序列表，而应包含 memory id、写入来源、最近检索事件、CMIS 分数、MCG 异常原因、融合 DS、建议动作和复核状态。建议动作至少分为 observe、downweight、quarantine、delete、rewrite 五类。observe 表示继续观察；downweight 降低检索权重；quarantine 暂时隔离；delete 删除；rewrite 保留可信片段并移除风险内容。

对于 rewrite，系统需要句子级或字段级定位。很多长期记忆不是纯恶意，而是“真实偏好 + 恶意附加规则”的混合。整条删除会损伤用户体验，句子级净化更合理。CMIS 可以先定位 memory item，随后用 LLM 或规则标出风险片段，再由人工或安全策略确认。

MemAudit 也应输出审计置信度。若 CMIS 高但 MCG 正常，可能是某条真实记忆在特定事件中被错误使用；若 MCG 高但 CMIS 低，可能是潜伏风险；若两者都高，才是最高优先级。把这三种情况区分开，能减少误删。

最后，审计系统应支持时间回滚。若发现某一时间窗口内写入大量污染记忆，可以回滚该窗口或提高该窗口记忆的风险权重。这个能力对事件响应很重要。

方法章再补一层数据结构。Memory item 应拆成 content、source、scope、confidence、last_verified_at、retrieval_count、linked_events 和 safety_labels。CMIS 主要作用在 linked_events，MCG 主要作用在 content 与关系边，处置策略则依赖 source、confidence 和 safety_labels。若记忆只是裸文本，MemAudit 的解释力会下降。

审计还要处理记忆压缩。很多 agent 会把旧记忆合并或摘要成更短条目，污染内容可能被摘要器改写后继续存在。此时删除原始 m_i 不一定有效，需要追踪 memory lineage：某条摘要记忆由哪些原始记忆合成。CMIS 应能沿 lineage 回溯，否则会误以为摘要本身是污染源。

对于结构异常，图更新频率也重要。每次写入新记忆都全量重建图成本高，可以增量更新新节点与近邻关系，定期做全量重算。高风险事件触发时，再临时扩展相关子图。这个实现策略能兼顾实时性和审计质量。

MemAudit 的实现还需要注意图构造与打分归一化的先后顺序。若先在全量记忆上直接比较 CMIS，容易让长文本记忆因为包含更多实体而获得偏高分；若先按实体、时间或主题切块建图，再在相邻或语义近邻节点之间计算冲突边，MCG 才更像“局部一致性”信号。复现时建议记录每条边的来源类型，例如显式矛盾、属性冲突、时间冲突、数值冲突或问答证据冲突，并在最终 DS 排序中保留可解释字段。这样不仅能复现表格分数，也能让审计结果真正服务长期记忆清理。

另一个容易被低估的细节是 evidence retrieval 的召回边界。论文把问题、答案与推理依据合成审计样本，但实际系统中证据可能散落在多个记忆条目里；如果检索窗口过窄，CMIS 会把缺证据误判成低冲突，如果窗口过宽，MCG 又会受到无关邻居干扰。比较可靠的做法是先用轻量检索形成候选子图，再在子图内做成对一致性判断，最后把节点级分数聚合回记忆条目。这也解释了为什么 α 融合不是装饰项，而是在“答案级证据”和“图级传播”之间做偏置控制。

从系统边界看，MemAudit 还需要一个可回滚的修复策略。审计器发现高风险记忆后，不应立即删除所有可疑条目，而应先输出证据、风险类型、影响范围和建议动作。建议动作可以分成保留、降权、隔离、等待人工确认和删除五类。这样的动作空间比二分类更适合长期记忆系统，因为一些记忆可能只是缺少时间戳或来源，而不是内容本身错误。论文的图打分框架可以自然支持这种分级处置：高 CMIS 且高 MCG 的节点优先隔离，单点冲突但图邻居正常的节点进入人工复核，低置信度节点只降低召回权重。

3. 实验结果

实验章按证据链阅读，而不是只摘最高指标。MemAudit: Post-hoc Auditing of Poisoned Agent Memory via Causal Attribution and Structural Anomaly Detection 的实验对象包括主结果、消融、效率或线上/影子评估；每一类结果都要和论文主张一一对应。

3.1 实验设置与主结果

实验覆盖 QA 和 RAP 两类任务，并比较随机删除、按检索频率删除以及 MemAudit。Table 1 的主结果显示，简单删除策略很难稳定降低 ASRafter，因为高频记忆未必是污染源，随机删除更可能损伤正常记忆。MemAudit 通过因果影响和结构异常排序，把删除预算集中在真正可疑的记忆上。

组件消融说明两条信号都必要。Table 2 比较 CMIS-only、MCG-only 和融合版本。PDF 文本提到，在 GPT-4o 设置下，单独信号仍留下较高 ASRafter，而融合后显著更低。这说明污染记忆既有因果影响维度，也有结构异常维度；只看一种视角会漏掉一部分攻击。

补充看主结果表时，随机删除和频率删除是两个很有必要的弱基线：前者说明只靠删除容量不能解决问题，后者说明高频记忆不一定就是攻击源。MemAudit 如果能在 QA 与 RAP 两类任务上同时降低攻击影响，才说明 CMIS 与 MCG 的融合不仅识别文本异常，也识别了对下游行为真正有因果影响的记忆。

这张主结果表应该在实验章阅读。它把不同 backbone、不同任务和不同删除策略放在同一张表中，核心指标是审计后攻击成功率 ASRafter。随机删除和检索频率删除代表两个朴素基线：前者没有利用风险信息，后者假设越常被检索越可疑。MemAudit 如果能在相同删除预算下降低 ASRafter，就说明它确实捕捉到了更贴近因果的风险记忆。读表时还要看不同任务之间是否一致；如果 QA 和 RAP 都改善，方法的可信度高于只在单一任务上有效。

3.2 消融、效率和分桶证据

Table 3 的 α 消融很有工程价值。论文报告 α 从 0.2 到 0.6 时性能改善，但 α=0.8 时下降，默认 α=0.6 在 QA 和 RAP 上表现最好。这说明反事实信号更强，但结构信号不可丢。若本地系统的记忆检索日志很完整，可以提高 CMIS 权重；若反事实重放成本高或风险评分不稳，则需要提高结构异常权重。

Table 4/5 研究污染比例 ρ。文本显示，在低污染密度下，MemAudit 可把 ASRafter 降到接近 0；当 ρ 增加到 0.25 或 0.50 时，效果明显退化。这个结果非常关键：post-hoc 审计不是万能清洗器，它适合处理少量污染或局部攻击；如果记忆库被大面积污染，异常模式会变成另一个“正常簇”，审计就更难。

3.3 结果边界与复现风险

Table 6 的定性案例展示了 MINJA 攻击下被识别出的可疑记忆。这类例子帮助理解模型为什么排序某条记忆：它可能包含伪装成偏好的恶意指令，或在多个任务中反复引导 agent 做出目标行为。对复现而言，定性样本应和数值表同等重要，因为它能暴露误删正常记忆或漏删组合投毒的风险。

补充实验解读时，QA 和 RAP 的差别值得关注。QA 更像问答污染，RAP 更接近行动或角色扮演场景。若 MemAudit 在两者上都能降低 ASRafter，说明它不只适用于某种文本输出，而能处理不同 agent 行为类型。

Table 2 的组件消融说明 CMIS 和 MCG 的互补性。CMIS-only 能抓住当前事件的因果记忆，但可能漏掉结构上异常但尚未强触发的污染；MCG-only 能发现离群记忆，但可能误伤真实少见偏好。融合版本更稳，说明安全审计不应押注单一信号。

污染密度实验是论文里最现实的风险提示。ρ 较低时，污染记忆像少数异常点，审计容易；ρ 较高时，污染记忆彼此支撑，甚至形成另一个一致簇，结构异常和单条反事实影响都会变弱。这与推荐系统里的刷量污染类似：少量异常账号容易发现，大规模协同攻击会改变分布本身。

实验结果还应按“删除预算”解读。若允许删除大量记忆，很多方法都能降低 ASR，但代价是个性化能力下降。更有意义的是在固定 top-k 删除预算下比较 ASRafter 和正常任务性能。论文主表关注 ASRafter，本地复现应额外加入正常记忆保持率和任务成功率。

定性案例的价值在于展示误报和漏报。Table 6 中的代表性 MINJA 样本可以帮助人工理解污染记忆如何伪装。复现时应保存高分误报样本，因为它们会告诉我们结构异常是否过度惩罚少见但真实的偏好。

实验可进一步读成三组问题。主结果回答“MemAudit 是否比朴素删除强”；消融回答“因果和结构是否都必要”；污染密度回答“方法何时失效”。这三组问题比单个平均 ASRafter 更有价值，因为它们分别对应采用理由、模块保留理由和上线边界。

对于 Table 4/5，ρ 从低到高的变化尤其像生产事故演进：早期只有少量污染，审计能快速清除；一旦污染扩散并互相支持，系统需要更强的隔离、回滚和人工调查。也就是说，MemAudit 应尽早运行，不能等记忆库大面积污染后再指望一次清洗解决。

实验应补充 clean utility。删除记忆后攻击成功率下降是好事，但如果正常问答准确率或个性化满意度大幅下降，系统仍不可用。建议在 QA/RAP 之外加入 clean tasks，比较审计前后正常行为保持率。

污染密度结果还提示需要早期预警。ρ 接近 0.25 后性能明显退化，说明大规模污染不适合只靠 post-hoc 排序解决。生产系统应在写入量、异常相似记忆簇和风险事件增加时提前报警。

实验还可以报告 precision at k。安全人员通常只会复核前几十条可疑记忆，因此 top-k 排序比全库平均准确率更有意义。若 MemAudit 能在 top-10 或 top-20 中集中命中污染源，它就能显著节省人工排查时间。

实验补充：MemAudit 的 qualitative examples 应用于校准人工标准。每次模型给出高风险记忆，人工需要判断它是攻击、过期事实、无害偏好还是模型误用。把这些判断回写后，才能改进后续风险标签。

实验部分还应把“污染强度”和“检测粒度”分开理解。表 4、表 5 的 contamination 设置说明，当错误记忆比例升高时，单条问答证据会更容易被邻近错误污染，因此高召回不必然意味着高可用性；而 MINJA 案例展示的是另一类问题，即模型在看似合理的长期记忆中生成自洽但错误的回答。对生产系统而言，前者对应批量清洗策略，后者对应在线回答前的风险提示，两者不能只用一个总准确率概括。

此外，评估时最好单独报告审计后的下游回答质量。只检测污染记忆还不够，真正目标是让使用这些记忆的模型少犯错。

4. 总结

4.1 我的判断

我的判断是，MemAudit 应被看作长期 agent 的安全运维组件，而不是单次离线清洗工具。它适合周期性扫描最近有害事件，生成待复核记忆队列，并为每个高风险记忆提供影响证据、结构异常证据和处理建议。

4.2 工程启发与复现建议

工程启发在于把 memory store 设计成可审计系统。每条记忆都应保留来源、时间、写入上下文、检索次数、影响事件和处理历史。没有这些字段，审计模型只能看静态文本，很容易误判少见偏好或漏掉跨会话污染。

4.3 局限与后续跟进

局限包括：反事实重放成本可能很高；风险评分器本身可能不稳定；结构异常会误伤真实但少见的用户偏好；大规模协同投毒会削弱单条记忆显著性；删除记忆可能破坏长期个性化连续性。后续应复现多条协同投毒、比较隔离和删除两种处理策略、为高风险记忆建立人工复核面板，并把审计结果和 agent 记忆写入策略联动。

后续复现不应只做单条恶意记忆。更有价值的是构造多条协同投毒、过期事实、真实少见偏好和格式伪装记忆，观察 MemAudit 如何排序。验收指标也不应只有 ASRafter，还要看人工复核 top-k 命中率、误删率、恢复成本和审计时延。

我会把 MemAudit 的后续工作分成检测、处置和学习三步。检测负责生成风险队列，处置负责隔离/删除/恢复，学习负责把人工复核结果回写到写入策略。只有这三步闭环，memory 审计才会越用越准。

总结补充：我会把 MemAudit 接到三个告警上，一是 harmful output 告警，二是记忆写入异常告警，三是高风险记忆反复检索告警。三类告警相互印证，才能减少误报。后续还应建立人工复核反馈，让 DS 分数能够按本地业务持续校准。

最终我会把 MemAudit 标为“需要安全闭环后再落地”。单独排序可疑记忆只是第一步，真正可用还要有隔离、恢复、人工复核和上游写入策略更新。

总结上，我会要求 MemAudit 复现同时报告三类指标：ASRafter、clean utility retention 和 human-review precision。缺少任一类，审计系统都不完整。

结论补充：MemAudit 的强项是解释“哪条记忆影响了哪次坏行为”，弱项是处理全库系统性污染。因此它更适合早期发现和局部净化，而不是灾后大清洗。 我会把 MemAudit 视为长期记忆系统的“离线质检层”，而不是在线推理时的万能防线。它适合周期性扫描、定位高风险记忆和生成可解释删除建议；若要直接拦截在线回答，还需要额外控制延迟、证据新鲜度和用户隐私边界。
