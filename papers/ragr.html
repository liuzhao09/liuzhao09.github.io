这里阅读一篇最近公开的论文《RAGR: Review-Augmented Generative Recommendation》。中文可以叫《评论增强的生成式推荐》。

论文链接：https://arxiv.org/abs/2605.17267 PDF：https://arxiv.org/pdf/2605.17267 代码/项目页：https://github.com/Zhang-Yingyi/TKDE_RAGR 公开日期：2026-05-17，来源：arXiv cs.IR，arXiv ID：2605.17267。

1. 一句话

这篇论文讨论一个很容易被生成式推荐忽略的问题：用户历史里只有 item ID 或 semantic ID 时，模型知道用户买过什么、点过什么，却不知道用户为什么喜欢。RAGR 的做法不是把 review 当成外部辅助特征拼到最后，而是把 review 本身也离散成 semantic IDs，按时间顺序和 item semantic IDs 交错进入同一条生成式用户序列。这样，评论里的尺寸、材质、风格、价格感、使用场景等主观偏好，会像 item token 一样参与自回归建模。

2. 研究问题

TIGER、P5、LC-Rec 一类生成式推荐方法把推荐改写成 token generation，核心优势是能够用统一词表和序列模型处理召回。但这些方法大多继承了序列推荐的 item-only 假设：用户序列是 item 的排列，用户反馈最多只体现在是否交互。论文指出这会形成结构性瓶颈，因为电商和内容平台里的评论反馈通常解释了选择背后的原因。两个用户买同一件商品，可能一个看重外观，一个看重功能；仅用 item semantic ID 会把这两种偏好压成同一个符号。RAGR 想回答的是：能不能把 review 的解释性信号变成生成式推荐的一等公民，同时又不让模型偏离“预测下一个 item”的主任务。

3. 核心方法

方法分三步。第一步训练 tokenizer，把 item 文本和 review 文本分别映射为离散 semantic IDs。第二步构造 Review-Augmented User Sequence：每次用户交互后，不只放入 item SID，也放入该次交互对应 review 的 SID，形成 item-review-item-review 的混合序列。第三步是 Item-Centric Task Generation Alignment。因为序列里混入了 review token，模型可能学会在预测位生成 review SID，而不是目标 item SID。论文用 DPO 构造 chosen/rejected 对，chosen 是目标 item semantic ID，rejected 是对应 review semantic ID，从训练目标上鼓励模型在推荐位置偏向 item。这个设计的关键不是“多加一个文本特征”，而是让 review 信号参与用户状态更新，同时用偏好优化约束输出空间。

5. 实验结果

论文在 Beauty、Toys、Sport 三个真实世界数据集上做实验，和多种生成式推荐 backbone 比较。摘要和表格给出的结论是 RAGR 在 HIT 与 NDCG 等指标上稳定超过强基线；消融显示，仅把 review 加入输入不够，还需要任务扩展和 DPO 式的 item-centric alignment，才能避免模型被 review token 带偏。tokenizer 实验也有工程价值：直接混合 item text 与 review text 训练 tokenizer 未必总是最优，说明 review 的价值主要在用户序列建模和任务对齐，而不一定在更大的混合语料 tokenizer 上。

6. 启发与局限

对推荐系统来说，RAGR 提醒我们生成式推荐不应只追求更好的 SID 量化，还要思考哪些行为解释信号应进入生成序列。它适合评论丰富、用户表达强的电商、酒旅、本地生活和内容平台。对大模型来说，它把 DPO 从对话偏好迁移到推荐 token 对齐，是 LLM 后训练思想在推荐序列上的一个清晰例子。局限也明显：评论覆盖率、评论质量和虚假评论会直接影响序列质量；没有评论的冷启动 item 需要 fallback；review token 增加序列长度，会推高训练和推理成本；DPO 的负样本构造也可能带来目标偏置。后续值得跟进代码公开后的 tokenizer 细节、review 缺失场景，以及是否能把图片/问答/售后反馈也统一进生成式用户序列。
