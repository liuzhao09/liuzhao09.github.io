这里重写精读 NVIDIA 的《Gated DeltaNet-2: Decoupling Erase and Write in Linear Attention》。论文入口：arXiv:2605.22791。作者为 Ali Hatamizadeh、Yejin Choi、Jan Kautz，机构 NVIDIA。代码仓库本轮可访问：https://github.com/NVlabs/GatedDeltaNet-2。本文关注 recurrent linear attention 的状态更新，核心是把 erase gate 和 write gate 解耦，让固定大小记忆更稳定地编辑旧信息并写入新信息。

1. 背景和问题

长上下文大模型的主流方案仍然依赖 softmax attention 和 KV cache，但上下文长度增加会带来训练和推理成本上升。线性注意力、状态空间模型和 recurrent attention 试图用固定大小状态替代随序列增长的 attention matrix，从而让长序列吞吐更稳定。问题是，固定状态本质上是一种压缩记忆：模型必须决定哪些旧关联应该被擦除，哪些新信息应该写入。如果状态更新不够精细，模型要么忘得太快，要么新旧信息互相覆盖。 DeltaNet 和 Gated DeltaNet 属于 fast-weight / linear attention 路线。它们把历史 key-value 关联写入一个状态矩阵，后续 token 通过 query 从状态中读取信息。已有 delta rule 通常用一个 gate 同时控制 erase 和 write，这在直觉上并不合理：擦除旧 key-side association 和写入新 value-side content 是两个不同动作。比如当前 token 可能需要强烈擦除某些旧关联，但只写入少量新值；也可能需要保留旧关联，同时写入补充信息。用一个 scalar gate 同时控制二者，会限制状态编辑能力。 Gated DeltaNet-2 的核心问题就是这个耦合。论文提出 Gated Delta Rule-2，用 channel-wise erase gate $b_t$ 和 channel-wise write gate $w_t$ 分别控制两个动作。它还结合 KDA 的 channel-wise decay，并推导 chunkwise WY algorithm 和 gate-aware backward pass，让训练仍然可以并行。这个工作不是 KV cache 压缩，也不是简单换一个长上下文 benchmark，而是改 recurrent linear attention 的基本状态更新算子。 对推荐系统也可以类比理解。用户序列建模里常有“旧兴趣擦除”和“新兴趣写入”：用户临时看了某类内容，不代表长期兴趣全部改变；用户长期偏好也不应被一次点击完全覆盖。如果序列模型用单一门控同时控制忘记和写入，就可能出现兴趣漂移。Gated DeltaNet-2 虽然是 LLM 架构论文，但它提出的 erase/write 解耦思想对序列推荐和长行为建模也有启发。

线性注意力路线常被概括为“复杂度更低”，但真正难点是记忆质量。固定大小状态意味着所有历史都被压缩进有限矩阵，长序列越长，冲突越多。Softmax attention 虽然贵，但它保留显式 token-token 关系；recurrent linear attention 便宜，却必须持续编辑同一个状态。Gated DeltaNet-2 的贡献应该放在这个背景下看：它不是把复杂度从二次降到线性这么简单，而是在问固定状态如何更像可控记忆。 这种问题在长上下文推理中非常具体。Needle-in-a-haystack、多键检索、长文 QA 都要求模型在大量干扰信息中保留少量关键关联。如果写入新 token 时覆盖旧 key，模型会忘记早期 needle；如果擦除太弱，状态会积累噪声。解耦 erase/write 是对这个矛盾的直接回应。

补充背景：这篇论文处在一个很明确的张力里：Transformer 的 KV cache 能精确保留上下文，但长序列成本高；线性注意力和 recurrent 模型能固定状态推理，但容易丢失或覆盖细节。Gated DeltaNet-2 不是简单声称“线性注意力替代 Transformer”，而是把问题缩小到状态更新规则：当一个新 token 到来时，模型到底应该擦除旧关联、写入新关联，还是同时做两件事。把这个动作拆开，是它相对一代 Gated DeltaNet 的关键变化。

2. 方法

2.1 从 Delta Rule 到 Gated Delta Rule-2

在线性注意力视角下，模型维护一个状态 $S_t$，每个 token 提供 key $k_t$、value $v_t$ 和 query $q_t$。读取可以抽象为 $o_t=q_t^\top S_{t-1}$，写入则更新 $S_t$。Delta rule 的思想是根据当前 key 读出的旧值与目标 value 之间的差，修正状态。Gated DeltaNet-2 的改动在于把修正动作拆成 erase 与 write 两部分，分别由 channel-wise gate 控制。 公式清单包括以下核心项。读取旧值：$\bar{v}_t=S_{t-1}k_t$。擦除项由 $b_t$ 控制，可理解为沿 key 方向删除旧关联；写入项由 $w_t$ 控制，可理解为把新的 value residual 写回状态。整体更新可以抽象成 $S_t = S_{t-1} - erase(b_t,k_t,\bar{v}_t) + write(w_t,k_t,v_t)$。论文具体公式更严谨，但直觉就是：不要让一个 gate 同时决定“旧内容删多少”和“新内容写多少”。

2.2 结构图：hybrid block 和 token mixer

Figure 1 左侧展示 Hybrid Gated DeltaNet-2：模型可以在 MLP、SWA 和 Gated DeltaNet-2 token mixer 之间组合；右侧展示 block design，Gated Delta Rule-2 位于 Norm 和 Linear 投影之间，并显式产生 erase/write 相关路径。图中最重要的是两个层次：架构层面，recurrent mixer 负责长程压缩，sliding-window attention 负责局部精确交互；算子层面，状态更新不再用一个统一 gate，而是把 key-side erase 与 value-side write 分开。这个结构解释了为什么它既能追求固定状态吞吐，又没有完全放弃局部 attention 的精确性。

2.3 Channel-wise gate 为什么重要

如果 gate 是 scalar，整个 channel group 同时被同等强度地擦除或写入，表达能力有限。Channel-wise gate 允许不同维度选择不同遗忘和写入强度。对于语言序列，某些维度可能对应实体、位置、句法或局部模式，不同维度的生命周期并不相同。Gated DeltaNet-2 让 $b_t$ 与 $w_t$ 都是 channel-wise，从而更细粒度地控制记忆状态。这也解释了论文在消融中比较 scalar gate、不同 erase range 和不同 hybrid 配置。若把 gate 压回 scalar，模型可能在多键检索或长程依赖上退化；若 erase 过强，会破坏旧信息；若 write 过弱，新 token 无法进入状态。Gated DeltaNet-2 的收益来自状态编辑更像“可控写缓存”，而不是一味扩大状态维度。

2.4 Chunkwise WY 与并行训练

Recurrent 结构容易推理高效，但训练并行性是难点。如果每个 token 状态都必须严格依赖前一个 token，长序列训练会变慢。论文因此推导 chunkwise WY algorithm，把一段 token 的更新合并成可并行计算的矩阵形式。Gate-aware backward pass 则保证 erase/write gate 的梯度能正确传播。这个部分很工程，但决定方法能否在 100B tokens 级别预训练。

从系统角度看，Gated DeltaNet-2 的目标不是做一个 toy recurrent layer，而是让 recurrent linear attention 能进入真实 LLM 训练。它在 1.3B 模型、100B FineWeb-Edu tokens 上比较多种架构，说明作者关注的是可训练性和吞吐，而不只是理论复杂度。对后续复现者，真正难点也在这里：公式可读，训练 kernel、chunking、backward 和 serving 支持才是门槛。

2.5 Hybrid with sliding-window attention

论文并没有声称 recurrent mixer 可以完全替代 attention。Hybrid block 中交替使用 SWA，说明局部精确 token-token interaction 仍然重要。Recurrent state 擅长长程压缩和固定成本记忆，但对精确复制、局部语法和短距离组合，SWA 仍有优势。因此 Gated DeltaNet-2 更像一种 hybrid long-context architecture：用 recurrent mixer 控制全局成本，用 SWA 保留局部细节。 这个判断对长上下文模型很重要。单纯追求线性复杂度可能牺牲精确检索；单纯扩大 attention window 又成本太高。Gated DeltaNet-2 的路线是在状态更新算子上提高记忆质量，再和局部 attention 组合。它与 ArborKV、KV cache compression 不同：后者是在已有 transformer cache 上做管理，本文是在模型结构内部改变记忆写入机制。

2.6 Fast-weight view

从 fast-weight 角度看，状态矩阵 $S_t$ 像一个可微记忆表，key 是地址，value 是内容。普通 delta rule 用当前 key 读旧值，再把旧值和目标值的差写入。Gated DeltaNet-2 把这个过程拆成两个门控动作：先决定沿当前 key 应该擦除哪些旧内容，再决定新 value 的哪些通道应该写入。这比单 gate 更接近真实内存编辑。

2.7 Erase gate 的作用

Erase gate $b_t$ 不是普通遗忘门。它作用在 key-side association 上，决定旧状态中与当前 key 相关的部分是否应被移除。如果当前 token 修正了前文实体或引入新的上下文，erase 可以防止旧关联继续影响后续读取。Channel-wise erase 允许模型只清理部分维度，而不是整体清空。

2.8 Write gate 的作用

Write gate $w_t$ 控制 value-side 新信息写入量。即使需要擦除旧关联，也不一定要大量写入新值；反过来，保留旧状态时也可能需要写入补充特征。把 write 独立出来能减少过度覆盖。对于语言模型，某些 token 只是连接词，不应强写记忆；某些实体、数字或指令则需要强写。

2.9 与 KDA / Mamba 的关系

KDA 引入 channel-wise decay，Mamba 系列强调选择性状态空间。Gated DeltaNet-2 与它们共享“状态应选择性更新”的思想，但具体落在 linear attention fast-weight update 上。它不是卷积或 SSM，而是保留 key-value 关联读写视角。因此它更容易和 attention 概念对齐，也更适合解释多键检索。

2.10 Hybrid block 的取舍

SWA 的存在说明作者没有把 recurrent state 神化。局部 token 交互仍然需要精确 attention，尤其是语法、短距离引用和格式化输出。Hybrid block 把长程记忆和局部细节分工：Gated DeltaNet-2 负责长距离压缩，SWA 负责窗口内精确匹配。这个分工比纯 linear attention 更现实。

2.11 训练 kernel 与复现门槛

Chunkwise WY 和 gate-aware backward 是实现核心。若只按公式逐 token 循环，训练效率无法与 Transformer 比较；若 backward 没处理 gate 依赖，训练不稳定。复现者需要关注 CUDA/Triton kernel、chunk size、数值稳定性、归一化位置和混合精度。论文开源仓库可访问，这是后续验证的重要入口。

2.12 公式审计：状态编辑比状态大小更重要

这篇论文的核心公式不是单个 attention score，而是 fast-weight state 的读写。读取可以写成 $o_t=q_t^\topop S_{t-1}$，旧 value 估计可以写成 $ar{v}_t=S_{t-1}k_t$，更新则围绕“旧关联删除”和“新残差写入”展开。重要之处在于，erase gate 与 write gate 不共享同一个控制量：$b_t$ 更像 key-side 的清理强度，$w_t$ 更像 value-side 的写入强度。这样模型可以做“只擦不写”“只写不擦”或“部分擦、部分写”。

从记忆角度看，固定状态模型失败常常不是状态维度太小，而是状态编辑过粗。单 gate 更新会把“当前 token 是否重要”和“旧内容是否应该删除”混成一个动作。Gated DeltaNet-2 把两个动作拆开后，多键检索任务更容易保留多个 key-value association。这个解释也说明为什么论文必须看 RULER multi-key，而不能只看困惑度。

2.13 训练并行性的真正门槛

Recurrent 结构在推理时天然顺序，但训练时若逐 token 循环，就很难和 Transformer 公平比较。论文的 chunkwise WY 和 gate-aware backward 解决的是这个门槛：把一段 token 的状态更新组织成可并行矩阵运算，同时在反向传播中正确处理 gate 对状态的影响。没有这个 kernel 层实现，公式上再漂亮也无法支撑 100B token 预训练。

复现者需要把“架构论文”和“系统实现”一起读。若只照着公式写 PyTorch for-loop，得到的吞吐结论没有意义；若只看 CUDA kernel 又不理解 erase/write 的语义，调参时很难定位性能变化。本文的工程价值正来自两者结合：状态规则更细，训练实现也足够接近生产形态。

2.14 推荐序列建模的迁移点

对推荐系统来说，用户兴趣状态也存在 erase/write 问题。用户看了一个新类目，并不总是要覆盖旧兴趣；用户明确负反馈某个主题时，可能需要擦除关联但不写入新偏好；短期热点可能需要强写但快速衰减。Gated DeltaNet-2 的思想可以迁移为用户状态更新模块：把“删除旧兴趣”和“写入新兴趣”拆成不同 gate，并按行为类型、时间间隔和上下文控制。

当然，推荐序列的监督信号和语言建模不同。语言模型每个 token 都有 next-token loss，推荐里曝光偏差和延迟反馈很重。迁移时应先做离线用户序列预测或召回实验，检查多兴趣保留、兴趣转移和负反馈消除，而不是直接替换线上排序主干。

3. 实验结果

3.1 实验设置

论文训练 1.3B 模型，数据为 100B FineWeb-Edu tokens。比较对象包括 Mamba-2、Gated DeltaNet、KDA、Mamba-3、Transformer/hybrid variants 等。评估覆盖语言建模、常识推理、RULER needle-in-a-haystack、多键检索、真实检索任务和吞吐。这个设置能同时回答三件事：模型质量是否足够、长上下文记忆是否改善、效率是否保留。

消融说明 gate 形式、erase range 和 hybrid 配置都会影响结果。把 gate 压成 scalar 或改变擦除范围会削弱性能，支持作者关于 erase/write 解耦的判断。不过实验规模仍是 1.3B 与 100B tokens，距离更大 dense/MoE 模型还有差距。另一个边界是 serving 生态：Transformer 有成熟 KV cache、FlashAttention、vLLM/SGLang 支持，而 recurrent linear attention 需要新的 kernel 和 runtime。即使论文代码可访问，生产部署仍要看推理框架是否跟进。

3.6 语言任务与长上下文任务要一起看

如果一个架构只在 RULER 强，但普通语言建模差，说明它可能只是对特定合成任务过拟合。Gated DeltaNet-2 同时给出 Pile/LAMBADA/常识推理和 RULER，读法更完整。Table 2 证明基础能力，Table 3 证明长程记忆，Figure 2 证明效率。三者缺一不可。

3.7 吞吐图的边界

吞吐图显示 recurrent/hybrid 架构在长序列下更平缓，但训练吞吐不等于端到端 serving 成本。真实推理还涉及 batch、prefill、decode、KV 或 recurrent state 管理、框架支持。若 serving 框架不支持高效 recurrent state，理论效率可能无法兑现。因此后续要看 vLLM、SGLang 或专用 runtime 是否跟进。

3.8 读表顺序

我会按 Table 2、Table 3、Figure 2 的顺序读实验。Table 2 说明新架构没有牺牲普通语言建模和常识推理；Table 3 说明它在长上下文、多键检索上确实改善固定状态记忆；Figure 2 再说明这种改善没有用明显吞吐损失换来。若只看其中一个表，都可能误判：长上下文强但普通任务弱，不适合作为通用 LLM backbone；吞吐强但质量差，只是系统技巧；质量强但吞吐差，则失去 linear attention 的意义。

3.9 消融该怎么看

消融中最值得看的是 gate 粒度和 hybrid 配置。若把 channel-wise gate 简化成 scalar，模型会失去按维度编辑状态的能力；若移除 SWA，局部精确匹配会变弱；若改变 erase range，多键检索会直接受影响。这些消融指向同一个结论：Gated DeltaNet-2 的收益不是来自参数量或训练数据，而是来自状态更新结构。后续若有更大模型结果，也应继续要求同样的消融，否则很难确认机制是否还成立。

4. 总结

4.1 我的判断

Gated DeltaNet-2 的关键贡献是把固定状态记忆中的“擦除”和“写入”拆开。它不像 KV cache 剪枝那样事后管理缓存，而是在模型更新规则中提升记忆编辑能力。对长上下文 LLM，这是一个值得跟踪的架构方向。

4.2 工程启发与复现建议

复现应先读 NVlabs 仓库中的 gate-aware backward、chunkwise WY 和 block 配置，再比较相同 tokenizer、数据和训练预算下的 Mamba-3/KDA/Transformer hybrid。不要只跑 RULER；还要跑普通语言建模、常识推理、长文 QA 和真实检索任务。若用于推荐序列建模，可以尝试把用户兴趣状态的遗忘和写入分开建模。

4.3 局限与后续跟进

局限包括：规模尚未证明到更大模型；精确复制能力仍需 SWA 辅助；训练复现成本高；serving 支持不成熟。后续应关注更大模型结果、与 Kimi Linear/Mamba-3 的公平比较、推理框架支持，以及该 erase/write 机制是否能迁移到用户行为序列或长期记忆模块。

4.4 我会如何复现

我会先用仓库跑小规模 sanity check：同一数据、同一 tokenizer 下比较 Gated DeltaNet、KDA、Gated DeltaNet-2；再单独替换 erase/write gate 看 RULER 多键任务变化；最后测不同序列长度的吞吐。只有同时复现质量和效率，才算验证论文主张。

4.5 后续问题

需要跟踪更大模型、MoE 版本、真实长文 QA、代码任务、serving kernel 和与 Kimi Linear/Mamba-3 的公平对比。如果这些结果成立，erase/write 解耦可能成为 recurrent linear attention 的标准组件。

4.6 后续观察清单

后续最值得看的是三件事：更大规模模型是否仍然保持质量与吞吐平衡；vLLM、SGLang 或专用 runtime 是否支持高效 recurrent state serving；erase/write 解耦是否能迁移到非语言序列，例如用户行为、代码执行轨迹和长期 Agent memory。若这三点都成立，它就不只是一个长上下文 benchmark 技巧，而可能成为固定状态模型的标准更新单元。
