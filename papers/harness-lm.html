HARNESS-LM: A Three-Phase Training Recipe for Harnessing SLMs in Sponsored Search Retrieval：面向 Sponsored Search Retrieval 的三阶段 SLM 蒸馏配方

论文入口：arXiv:2605.23572。作者：Vipul Gupta, Shikhar Mohan, Lakshya Kumar, Pranjal Chitale, Nikit Begwani, Amit Singh, Manik Varma。机构口径：Microsoft AI India。代码/项目页状态：未核验到独立开源仓库；包含 Bing Ads 内部 benchmark 与线上 A/B。主类别：推荐算法；公开日期：arXiv submitted 2026-05-22。

用强 SLM teacher 建质量上界，再通过 query representation alignment、剪枝和 contrastive refinement 蒸馏出能在线上赞助搜索低延迟部署的 student retriever。 本笔记按当前流水线的精读要求重写：先记录公式清单、方法模块清单和图表清单，再围绕论文原文的任务设定、训练/推理链路、实验表和工程边界展开。

1. 背景和问题

HARNESS-LM 关注 sponsored search retrieval 中的质量-延迟矛盾。广告检索需要在极短时间内从海量候选中找出相关广告；大 SLM embedding 模型在公开检索 benchmark 上很强，但直接上线到广告召回会遇到 latency、throughput 和成本限制。论文因此提出三阶段 recipe：先训练强 teacher，建立质量上界；再把 teacher 的 query 表示蒸馏到小 student；最后用 contrastive refinement 恢复检索区分度。

这篇论文值得细读，是因为它不像许多蒸馏论文只报告离线指标，而是明确围绕 production deployment。它讨论 embedding dimension、prompt、features、loss、teacher quality、query alignment、layer/FFN pruning、latency-quality trade-off 和 online A/B。换句话说，方法目标不是“让小模型像大模型”，而是在 sponsored search 的线上约束下保留足够检索质量。

对大模型系统也有启发。RAG 和 agent retrieval 经常遇到同样问题：强 retriever 太慢，小 retriever 质量不足。HARNESS-LM 的做法提示我们，可以把大模型能力拆成 teacher 上界、表示对齐、结构压缩和在线对照四个阶段，而不是直接选择“大而慢”或“小而弱”。

更具体地说，HARNESS-LM: A Three-Phase Training Recipe for Harnessing SLMs in Sponsored Search Retrieval 的问题不应被读成单点模型改进，而应读成系统状态如何被建模、验证和服务化。旧链路通常把关键状态分散在人工规则、离线日志、缓存、业务策略或一次性 prompt 里，最终只能看到平均指标，却无法解释指标变化来自哪里。本文把这些状态拉回可观察接口：输入是什么，输出是什么，何时训练，何时推理，失败时如何定位。

这也是它和今天其他论文共同的地方：LLM 方向在处理 skill、memory、context，推荐方向在处理 user story、retriever distillation 和 generative backbone。它们都说明模型能力越来越依赖外部状态管理。阅读这篇论文时，我会持续追问三个问题：第一，论文是否明确记录了状态来源；第二，方法是否有独立验证或对照；第三，结果是否足以支持生产迁移，而不是只在某个离线表里好看。

补充背景时，要看到 sponsored search retrieval 与普通语义检索的差别。广告检索不仅要相关，还要受预算、竞价、地域、审核和商业目标约束。强 SLM embedding 在公开 benchmark 上表现好，并不意味着可以直接替换线上召回，因为 query encoder 的每毫秒延迟都会影响吞吐和收入。HARNESS-LM 的问题定义因此是生产检索，不是学术 reranking。

论文把“大 teacher、小 student”拆成 recipe，而不是只做一次蒸馏。这很重要，因为广告检索中的 teacher 质量、embedding dimension、prompt、features、hard negative 和剪枝都会改变最终 Pareto。若没有三阶段流程，student 很可能只是小模型 fine-tune，无法继承大 teacher 的语义几何。

对 RAG 工程也类似。很多系统希望使用强 embedding 模型，但线上延迟、成本和 index 维度不允许。HARNESS-LM 提供了一条路线：用强模型建立检索空间，再把 query side 压缩到可部署模型，同时保持 document side 和 ANN index 的稳定。

背景里还要强调广告检索的非对称性。Document/ad 侧可以离线计算、批量更新和压缩，query 侧必须实时响应用户请求。因此 HARNESS-LM 选择压缩 query encoder，而不是简单训练一个对称小双塔。这个决策与生产路径高度绑定，也是论文比普通 embedding distillation 更有价值的地方。

背景补充一点：HARNESS-LM 的价值在于承认“公开 embedding 排行榜强”与“广告召回可上线”之间有很长距离。广告系统的召回模型必须在固定机器、固定 SLA、固定 index 结构下工作。论文把 teacher 作为训练工具，而不是上线目标，这一点非常务实。

2.2 论文核心流程

第一阶段是 teacher retriever。论文使用 billion-scale SLM teacher，例如 Qwen3-Embedding-4B/8B 类模型，通过对称或非对称设置在 sponsored search 数据上训练。teacher 的作用不是上线，而是提供质量上界和 embedding 几何。Table 1/2/3 说明 teacher 的维度、prompt、feature 和 loss 选择会显著影响结果，因此这个阶段要先把大模型能力调到合理上限，再谈蒸馏。

第二阶段是 query representation alignment。赞助搜索线上路径通常对 query encoder 的延迟最敏感，而 document/ad 表示可以离线预计算。HARNESS-LM 因此重点让小 student query encoder 对齐 teacher query 表示。L2 alignment 目标比直接训练排序标签更稳定，因为它传递的是 teacher embedding 空间中的几何结构：哪些 query 接近、哪些 query 需要分开、哪些语义方向对广告检索重要。

补充看这张图时，要注意三阶段的顺序约束。Teacher retriever 先给出高质量表示和排序信号，alignment 阶段把学生查询向量拉向教师空间，contrastive refinement 再让学生适配真实 sponsored search 负样本。若直接从第三阶段开始，小模型容易在噪声负样本上欠拟合；若只有第一、二阶段，又未必能适配在线召回分布。

这张框架图把 HARNESS-LM 的三阶段逻辑放在一起。左侧是强 teacher 训练，用大 SLM 建立高质量检索空间；中间是 query alignment，把小 student 的 query 表示拉向 teacher；右侧是 contrastive refinement，在正负样本上恢复线上检索边界。图中最重要的是阶段顺序：如果没有 teacher 上界，student 缺少学习目标；如果没有 alignment，剪枝后的小模型难以继承语义空间；如果没有 CR，student 可能只像 teacher 的平均表示，却不能处理 sponsored search 的边界样本。

2.3 训练目标与优化控制

对齐目标还涉及投影和旋转。student 表示维度、teacher 表示维度和线上 index 维度未必一致，论文使用投影或 rotation alignment 处理空间差异。这个细节很工程化：如果只追求离线相似度，可能得到无法接入现有 ANN index 的向量；如果只追求线上维度，student 又可能丢失 teacher 的判别方向。

剪枝阶段进一步压缩 student。论文用 layer/FFN importance 衡量哪些层或前馈单元可以移除，并在剪枝后重新 alignment。这个流程比一次性蒸馏更稳，因为结构压缩会破坏 embedding 几何，需要再用 teacher 修正。Table 6 显示逐步剪枝和重对齐的影响，帮助选择质量和延迟的 Pareto 点。

2.4 推理链路、服务约束与系统接入

第三阶段 contrastive refinement 用真实正负样本恢复排序边界。L2 alignment 让 student 接近 teacher，但不一定在每个线上边界样本上最优；contrastive refinement 重新使用 query-document 对，让模型在 hard negatives 和 in-batch negatives 上学习区分。论文把 CR 放在 alignment 后面，是因为先有 teacher 几何，再做任务判别，训练会更稳定。

推理时，HLM 的目标是替换或增强线上 query encoder。document/ad embeddings 可离线产出，query embedding 实时生成，再与候选或 ANN index 做内积召回。这个路径要求模型小、维度合适、batching 可控、p99 latency 符合广告系统预算。论文报告 190M student 和多个延迟-质量点，说明方法从一开始就在服务约束内设计。

2.5 复现时应检查的实现细节

复现 HARNESS-LM: A Three-Phase Training Recipe for Harnessing SLMs in Sponsored Search Retrieval 时，应把论文模块拆成可观测的输入、输出、训练目标、推理路径和失败样本。每个模块都要记录数据来源、版本、延迟、成本、可回滚策略和与基线的差异。只有这些信息完整，论文结果才有本地迁移价值。

2.6 模块间信号流与落地检查

第一阶段 teacher 训练要把质量上界做实。论文比较 Qwen3-Embedding 4B/8B、LoRA rank、embedding dimension、prompt 和 loss。这个阶段若做弱，后续所有 student 都受限。对本地复现，teacher 阶段应保留完整训练配置和离线评测表，因为它是蒸馏目标的来源。

第二阶段 alignment 的核心是只压 query side。广告或文档 embedding 可以离线批量计算，query embedding 必须实时计算。把 student query encoder 对齐到 teacher query encoder，可以显著降低线上延迟，同时尽量保留 teacher 空间中的 query 语义。

L2 alignment 与 contrastive loss 的作用不同。L2 让 student 学 teacher 表示的几何位置，适合稳定迁移；contrastive loss 让模型直接区分正负广告，适合修复排序边界。HARNESS-LM 先 alignment 再 CR，是因为直接让小模型面对 noisy ads negatives 可能不稳定，而 teacher 表示提供了更平滑的初始化。

剪枝不是简单删层。论文用 layer 和 FFN importance 估计组件贡献，再剪掉低影响部分，并重新 alignment。这样做可以避免一次性结构压缩破坏 embedding 空间。真实系统还应检查剪枝后向量分布是否改变 ANN 召回、是否需要重建 index。

Table 9 的 latency-quality trade-off 也反过来约束方法。若某个 student 只在离线 P@100 上好，但 latency 仍接近 teacher，就没有部署价值；若极快但 precision 掉太多，也会损伤广告收入。HARNESS-LM 的方法始终围绕 Pareto 点选择。

线上 A/B 阶段说明 student 不是只跑离线 benchmark。广告系统的 revenue、click、impression lift 会受竞价和预算影响，因此 A/B 是必要证据。不过论文摘要没有完全展开置信区间和分桶，复现或迁移时仍要补充分行业、长尾 query 和新广告冷启动。

Teacher 阶段的 oracle input 和 feature 选择会影响上界。广告系统可能有历史点击、广告类目、landing page、竞价信息或质量分，这些特征有些线上可用，有些只适合训练。论文的 ablation on prompt, features, and loss 说明 teacher 质量来自输入、模型和损失三者共同作用。

Alignment corpus A 的覆盖范围也很重要。若 A 只包含高频商业 query，student 会在长尾 query 上退化；若 A 包含噪声 query，L2 目标会把噪声也传给 student。复现应按 query 频次、行业、语言、长度和新广告覆盖分层采样。

Query encoder alignment 看似简单，但它改变的是向量空间几何。Student 不只要接近 teacher 的单点表示，还要保留 query 之间的相对关系。若整体 MSE 低但近邻结构变化大，ANN 召回仍会坏。因此本地检查应加入 nearest-neighbor overlap、rank correlation 和 hard-negative 边界样本。

剪枝重要性指标需要校准集 C。C 如果太小或分布偏，会错误删除对长尾 query 重要的层。剪枝后重新 alignment 是必要步骤，因为结构变化会旋转或压缩表示空间。线上 index 是否需要重建，也取决于剪枝后向量分布变化。

Contrastive refinement 的 hard negative 设计决定最终边界。广告检索里的 hard negative 不是随机广告，而是看起来相关、可能竞价、但不应召回的广告。若 hard negative 太弱，CR 提升有限；若太强且标注噪声大，模型可能过拟合人工边界。

最后，线上 A/B 与离线 P@100 之间可能不一致。广告展示受预算和竞价影响，一个检索模型提升 relevance 也可能改变竞价分布。论文报告 revenue/click/impression lift 是强证据，但迁移时必须重新评估商业目标。

Teacher-student 关系还可以看作能力蒸馏与服务解耦。Teacher 可以使用更大模型、更高维 embedding、更复杂 prompt 和训练期特征；student 必须满足线上 query path。关键是不能让 teacher 依赖 student 永远拿不到的信息，否则 alignment 只能学到不可实现的空间。论文的 oracle input 讨论正好提示了这个风险。

Embedding dimension 的选择不仅影响模型输出，还影响 ANN index。较高维度会增加存储、内存带宽和搜索成本；较低维度会压缩语义空间。Table 2 的意义在于找到部署可接受的维度，而不是追求 teacher 的最高分。

Alignment loss 的训练曲线需要和检索指标一起看。L2 loss 持续下降不代表 P@100 一定上升，因为模型可能在平均意义上接近 teacher，却在 hard negatives 上没有足够边界。因此 Figure 2 和 Table 7 要结合：前者看对齐是否收敛，后者看 CR 是否恢复边界。

Layer/FFN pruning 的风险是破坏某些行业或长尾 query 的专门能力。平均 P@100 下降小，不代表所有分桶都安全。广告系统应按行业、地域、query 频次和新广告分桶看剪枝影响。若某些高价值行业退化，即使总体指标稳定，也不应上线。

Latency 表里的吞吐同样重要。低单 query latency 不一定代表高 QPS，如果模型 batch 效率差或 GPU 利用率低，生产成本仍高。Table 9 同时报告 latency 和 throughput，说明部署决策应基于完整成本。

Online A/B 还要避免归因过度。Revenue lift 可能来自更好相关性，也可能来自流量、预算、拍卖策略或季节因素。论文报告线上结果是强信号，但外部读者仍应关注实验时长、置信区间和分桶。

HARNESS-LM 还需要关注线上索引兼容性。Student query encoder 输出分布若与旧 document embeddings 不匹配，可能需要重建广告向量库；重建本身有成本和回滚风险。论文强调 query alignment，就是为了尽量保持与 teacher/document side 的空间兼容。复现时应检查新旧 query embedding 在同一 index 上的召回重合率。

训练语料还应包含 hard negatives 的生命周期。广告内容、竞价和用户意图变化很快，过去的 hard negative 可能后来变成可接受广告，或者反过来。CR 阶段如果使用过期负样本，会让 student 学到错误边界。

部署时还要设计双轨流量。新 student 可以先只参与 shadow retrieval，记录它会召回哪些广告、旧系统会召回哪些广告、两者差异是否集中在高价值 query。只有差异可解释，才适合进入小流量。

方法章还应说明部署前校准。Student 输出分数可能和旧检索模型分布不同，即使排序相对合理，也会影响后续融合、阈值和候选截断。上线前需要做 score calibration，把新 student 分数映射到旧系统可接受范围，或调整后续排序的特征归一化。

另一个实现点是双写 embedding。上线迁移期间，可以同时计算旧 query embedding 和 HLM query embedding，记录两者召回集合差异。这个双写阶段不影响用户体验，却能发现 HLM 是否在特定行业、短 query、长 query 或冷启动广告上偏离旧系统。

CR 阶段还应关注 label freshness。广告点击和相关性会随季节、活动、预算变化。若训练负样本过旧，student 可能拒绝当前其实有效的广告。因此 CR 数据需要时间衰减或滚动更新。

方法章再补充一个 teacher 选择标准。Teacher 不一定越大越好，如果 8B teacher 比 4B teacher 只带来很小提升，却显著增加训练成本和蒸馏难度，可能不值得。Table 4 的 teacher quality 实验应读成成本-上界选择，而不是单纯排名。

Student 侧还应监控 embedding norm。若 alignment 后向量范数分布偏移，内积打分会改变候选截断阈值。可以在训练中加入 norm regularization，或在上线前做向量归一化校准。

HARNESS-LM 的 recipe 还可扩展到多 teacher。一个 teacher 可能擅长语义相关，一个 teacher 擅长商业转化，融合 teacher 表示或蒸馏多个目标可能更适合广告。只是多 teacher 会增加目标冲突，需要额外权重和验证。

HARNESS-LM 的方法可以理解为“先确定教师能力边界，再把学生压到可服务形态”。第一阶段的教师并非只提供软标签，而是定义检索任务中哪些 query-document 关系值得保留；第二阶段通过表示对齐把这种能力投射到较小模型；第三阶段再用剪枝和压缩控制延迟。这个顺序很关键：如果先剪枝再对齐，学生容量不足会让知识迁移变成噪声拟合；如果只做蒸馏不做结构压缩，又难以达到在线检索的延迟目标。

双塔检索场景还要求训练目标和服务形态一致。文档向量通常离线构建，查询向量在线生成，所以任何跨编码器式的交互特征都不能直接放进最终模型；论文通过 query tower 与 document tower 的内积相似度维持 ANN 检索兼容性。复现时应分别记录塔结构、向量维度、归一化方式、负样本策略和离线索引刷新频率，否则表面上相同的蒸馏损失可能对应完全不同的召回性能。

3. 实验结果

实验章按证据链阅读，而不是只摘最高指标。HARNESS-LM: A Three-Phase Training Recipe for Harnessing SLMs in Sponsored Search Retrieval 的实验对象包括主结果、消融、效率或线上/影子评估；每一类结果都要和论文主张一一对应。

3.1 实验设置与主结果

实验首先验证 teacher。Table 1 报告不同 teacher retriever 的性能，Table 2 研究 embedding dimension，Table 3 比较 prompt、features 和 loss。这里的结论是 teacher 本身必须足够强，并且训练设置会影响后续蒸馏上限。若 teacher 质量不足，student alignment 只能继承一个低质量空间。

Table 4/5 检查 teacher quality 和 query alignment。论文文本指出，更强 teacher 带来更好的 student，但 teacher-student 差距也可能变大，说明蒸馏并不自动无损。固定 teacher 时，对齐细节决定 student 能否接近上界。Figure 2 的 alignment loss 曲线用于观察训练是否稳定收敛；如果 loss 下降但检索指标不涨，说明 L2 空间接近不等价于排序边界恢复。

补充看这张表时，latency-quality trade-off 是 HARNESS-LM 最贴近生产的证据。Sponsored search 召回必须在很短时间内生成查询向量并进入 ANN 检索，因此 40ms 到 6.8ms 级别的差异会直接影响能否上线。表中若质量下降很小而延迟下降显著，就说明三阶段训练没有只追求离线精度，而是在服务预算内重新分配模型容量。

这张 latency-quality 表是 HARNESS-LM 最接近部署决策的证据。它把 student 规模、维度、延迟、吞吐和检索质量放在一起，迫使读者同时考虑 precision 和 p99 成本。读表时不要只选最高 precision，也不要只选最低 latency；真正可用的点应位于 Pareto 前沿，并满足线上广告召回预算。论文报告的 40.96ms 到 6.8ms 延迟下降说明压缩确实有效，但 precision 小幅下降也提醒我们：小模型上线前必须用 shadow traffic 和 A/B 验证商业指标。

3.2 消融、效率和分桶证据

Table 6 研究剪枝。文本提到剪掉少数层时质量只小幅下降，而更多剪枝会带来明显损失。这为部署提供选择：如果线上预算极紧，可以接受一定 precision 下降换取 latency；如果业务对召回质量更敏感，就选择较少剪枝的 student。

Table 7/8 分析 contrastive refinement 和 asymmetric fine-tuning。CR 的价值在于修复 alignment 不能覆盖的 hard-negative 边界；asymmetric fine-tuning 则比较 query side 与 document side 的训练选择。赞助搜索里 document/ad side 往往离线可算，因此 query side 的实时成本更关键。

3.3 结果边界与复现风险

Table 9 是工程决策表。论文文本提到某设置可实现约 6 倍 latency reduction，从 40.96ms 到 6.8ms，同时 precision 从 64.3 降到 63.1，约 1.1% 下降。这个结果不应只理解为“更快”，而应读成质量-延迟 Pareto：业务需要决定这 1.1% precision 是否能被吞吐、成本和线上 A/B 收益抵消。Table 10 的线上 A/B 进一步验证 revenue、click、impression lift，证据等级高于纯离线 benchmark，但仍需看显著性、流量分层和广告预算影响。

补充实验时，Table 2 的 dimension 分析很实用。embedding 维度越大通常质量越好，但 index 内存、带宽和 query-doc scoring 成本也增加。论文在 d=128 等部署友好设置下比较结果，说明它考虑的是线上可用向量，而不是无限增大维度。

Table 3 的 prompt/features/loss 消融说明 teacher 不是黑盒。广告检索输入中可能包含 query 文本、广告文本、landing page、历史点击等特征，不同组合会影响 teacher 上界。若复现只用 raw query-document 文本，可能低估方法。

Figure 3 的二维投影展示训练阶段中 query 和 document embedding 如何靠近或分离。可视化不是主要指标，但能帮助发现 alignment 后空间是否坍缩、CR 后正负样本是否分开。对工业检索，embedding 空间形态直接影响 ANN index 的稳定性。

实验中的 Table 10 线上 A/B 应放在证据链末端。离线 P@100 证明模型能检索相关广告，latency 表证明它能部署，A/B 才证明它在真实拍卖和用户行为中有收益。三个证据缺一不可。

Table 11 的 oracle input 示例也值得看。它说明 raw query 之外的信息可能显著帮助 teacher，但这些信息未必线上可用。蒸馏时要小心 teacher 使用了 student 推理时拿不到的特征，否则 student 学到的是不可实现的上界。

实验补充一个读法：HARNESS-LM 的每个表都对应 recipe 中的一个决策。Table 1 选 teacher，Table 2 选维度，Table 3 选 teacher 训练设置，Table 4/5 选 alignment，Table 6 选剪枝强度，Table 7/8 选 CR/fine-tuning，Table 9 选部署点，Table 10 验证线上收益。这个顺序就是复现路线。

如果本地只复现最后的 student，而不复现前面的决策表，就很难知道失败原因。可能是 teacher 不够强，可能是 alignment 语料不覆盖，可能是剪枝过度，也可能是 CR negative 太弱。

实验补充一点：Table 9 的 6x latency reduction 应结合硬件利用率看。若延迟下降但 GPU 利用率低，成本未必最优；若吞吐上升且 precision 保持，才是更好的部署点。

线上 A/B 还需要观察预算消耗。更好的检索可能让某些广告更快耗尽预算，影响后续流量分布。广告系统的模型评估不能只看即时 click。

实验上，建议把 Table 9 的 Pareto 点投到成本模型中：GPU 数、QPS、batch size、index latency 和业务收益一起算。只有质量收益覆盖服务成本，才是真正可部署。

实验补充：建议在 P@100 之外加入 recall@k、NDCG、query latency p95/p99、GPU memory 和 ANN search time。广告检索瓶颈可能不在 encoder 本身，而在整体召回链路。

4. 总结

4.1 我的判断

我的判断是，HARNESS-LM 是广告检索和工业 RAG retriever 都值得参考的蒸馏流程。它的价值不在某个单独 loss，而在 teacher 上界、表示对齐、结构压缩、contrastive refinement 和线上 A/B 构成完整链条。

4.2 工程启发与复现建议

工程启发包括：先训练强 teacher 再蒸馏，不要用弱 teacher 限制 student；query side 是实时瓶颈，应重点压缩；alignment 后仍需任务级 CR；latency-quality 表比单一离线指标更重要；线上 A/B 必须同时看 revenue、click、impression 和预算约束。

4.3 局限与后续跟进

局限包括：Bing Ads 数据和负样本策略不可公开复现；teacher 偏差会被 student 继承；广告检索受竞价和预算影响，precision 不等于商业收益；剪枝和低维表示可能伤害长尾 query；线上收益的显著性和分桶细节未完全展开。后续应复现 teacher-student query alignment、画不同维度和剪枝强度的 Pareto 曲线、加入长尾 query 与新广告分桶，并比较 HLM 与直接小模型 LoRA 的差异。

后续复现应先构建小型 teacher-student 检索实验，固定 query/document 切分、hard negative、维度和 ANN index，再比较 teacher、直接小模型 fine-tune、alignment student、alignment+CR student。除 P@100 外，还要记录 latency、throughput、index size、长尾 query 和新广告分桶。

后续复现要特别关注 teacher 是否使用训练期特权信息。若 teacher 看到了线上 query encoder 看不到的特征，alignment student 可能只能近似表面几何，无法在真实请求中保持收益。实验报告应单独列出 train-only features 和 online-available features。

总结补充：我会把 HARNESS-LM 视为“检索模型生产化 recipe”。它适合广告、RAG、搜索召回等任何 query path 严格受限的系统。下一步最值得做的是把各阶段决策表自动化，形成从 teacher 到 student 的可重复流水线。

最终我会把 HARNESS-LM 作为检索蒸馏标准模板，但迁移前必须确认 teacher 特征、student 线上输入和 index 结构三者一致。

总结上，HARNESS-LM 可作为工业检索压缩模板，但必须和 score calibration、双写 shadow 和滚动 hard negative 更新一起使用。
